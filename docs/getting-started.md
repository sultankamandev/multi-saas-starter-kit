# Getting Started

Your first 15 minutes with a project generated by `npx create-saas-app`.

Everything below refers to paths **inside your generated project**, which looks like this
regardless of which stack you picked:

```
my-project/
├── backend/            # the backend template you chose
├── frontend/           # the frontend template you chose
├── docker/             # Dockerfiles (only if you chose Docker)
├── docker-compose.yml  # (only if you chose Docker)
└── docs/openapi.yaml   # the API contract your backend implements
```

## Option A — Docker (fastest)

Requires Docker Desktop (or Docker Engine + compose v2).

```bash
docker compose up --build
```

This starts PostgreSQL, the backend, and the frontend. The backend waits for Postgres to
pass its healthcheck before starting, and the database schema is created automatically on
first boot.

| Service | URL |
| ------- | --- |
| Frontend (Next.js) | http://localhost:3000 |
| Frontend (React / Vue SPA) | http://localhost |
| Backend (Go / Node) | http://localhost:8080 |
| Backend (Python) | http://localhost:8000 |
| PostgreSQL | localhost:5432 (`postgres` / `postgres`, db `saas_app`) |

Then skip ahead to [Create your first admin user](#create-your-first-admin-user).

> The frontend's API URL is baked in at **build** time (both Vite and Next.js inline public
> env vars into the client bundle). `docker-compose.yml` passes it as a build arg. If you
> change the backend port, rebuild with `docker compose build --no-cache frontend`.

## Option B — Run locally

### 1. PostgreSQL

You need a PostgreSQL 16 database. The quickest way, without running the whole stack:

```bash
docker run --name saas-pg -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=saas_app -p 5432:5432 -d postgres:16-alpine
```

Or install PostgreSQL natively and create a database named `saas_app`.

You do **not** need to run migrations by hand. Every backend creates its tables on
startup (GORM automigrate / SQLAlchemy / Drizzle).

### 2. Backend

```bash
cd backend
cp .env.example .env
```

Open `.env` and set, at minimum:

| Variable | What to put |
| -------- | ----------- |
| `DATABASE_URL` | Connection string for the database above. The format differs per stack — the value already in `.env.example` is correct for a local Postgres on port 5432. |
| `JWT_SECRET` | Any long random string. **Change this before deploying.** |
| `FRONTEND_URL` | Where your frontend runs, e.g. `http://localhost:3000`. Used for CORS and for links in emails. |
| `CORS_ORIGINS` | Same origin as above. Browsers omit the default port, so use `http://localhost` (not `http://localhost:80`) for an SPA served on port 80. |

Everything else (SMTP, Google OAuth, reCAPTCHA) is optional to boot — see
[Email in development](#email-in-development) below.

Then install and run, using the commands for your stack:

| Stack | Install | Run |
| ----- | ------- | --- |
| Go (Gin) | `go mod download` | `go run ./cmd/server` |
| Python (FastAPI) | `pip install -r requirements.txt` | `uvicorn app.main:app --reload` |
| Node (Express) | `npm install` | `npm run dev` |

Check it: `curl http://localhost:8080/ping` (or `:8000` for Python) should return
`{"message":"pong"}`.

### 3. Frontend

```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```

The one variable that matters is the API URL — `NEXT_PUBLIC_API_URL` for Next.js,
`VITE_API_URL` for the React and Vue SPAs. It must point at your backend
(`http://localhost:8080` or `http://localhost:8000`).

## Create your first admin user

**There is no seed script and no default admin account.** Everyone who registers gets
`role = 'user'`, so the admin console at `/admin` is unreachable until you promote an
account yourself.

1. Register normally through the frontend (or `POST /auth/register`).
2. Promote that account directly in the database:

```bash
docker exec -it saas-pg psql -U postgres -d saas_app -c "UPDATE users SET role = 'admin', verified = true WHERE email = 'you@example.com';"
```

If you are not using Docker for Postgres, run the same `UPDATE` in `psql` or any SQL client.

Log out and back in — the new role is embedded in the JWT, so an existing token still
says `user` until you get a fresh one.

## Email in development

Registration, email verification, password reset, and email-based 2FA all send mail over
SMTP. With no `SMTP_*` values configured, those sends fail and the flows that depend on
them will not complete.

Two ways to unblock local development:

- **Turn email verification off.** Once you have an admin, `PUT /api/admin/settings/email-verification`
  with `{"require_email_verification": false}`, or set the `require_email_verification` row
  in `app_settings` to `false`. New accounts are then usable immediately.
- **Catch mail locally.** Run a dev SMTP catcher such as Mailpit
  (`docker run -p 1025:1025 -p 8025:8025 axllent/mailpit`) and point your `.env` at it:
  `SMTP_HOST=localhost`, `SMTP_PORT=1025`, and leave `SMTP_USER` / `SMTP_PASS` empty.
  Every outgoing message shows up at http://localhost:8025.

## Where things live

| You want to change... | Look in |
| --------------------- | ------- |
| An API endpoint | `backend/` — see its `README.md` for the layering |
| The API shape itself | `docs/openapi.yaml` (the contract your backend implements) |
| A page or component | `frontend/src/` |
| Translations | Next.js: `frontend/messages/<lang>.json` · React: `frontend/public/locales/<lang>/translation.json` · Vue: `frontend/public/<lang>/translation.json` |
| HTTP client, auth token handling | `frontend/src/lib/api.ts` |

## Troubleshooting

**CORS errors in the browser.** `CORS_ORIGINS` on the backend must match the frontend's
origin exactly, including scheme and port. A frontend on port 80 has origin
`http://localhost`, with no port.

**Frontend calls go to the wrong host in Docker.** The API URL is compiled into the
bundle, so it must be reachable from your *browser* — `http://localhost:8080`, never the
compose service name `http://backend:8080`.

**401 immediately after logging in.** Access tokens are short-lived and refreshed
automatically. If refresh also fails, `JWT_SECRET` most likely changed between restarts,
which invalidates every previously issued token.

**Admin pages return 403.** Your JWT still carries the old role — log out and back in
after promoting the account.
